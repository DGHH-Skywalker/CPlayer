# 校园课间调度

## 状态与优先级

调度状态为 `DISABLED`、`CLASS`、`BREAK`、`TRANSITIONING`。`CLASS` 和 `TRANSITIONING` 均禁止开始或恢复播放。进入 `CLASS` 时先更新主进程闸门，再停止原生及流媒体音频、停止附属媒体、清空当前队列和随机队列备份。

队列清空采用串行写入。清空操作等待旧写入完成，写入空数组和 `null`，再读回 `playList` 与 `originalPlayList`；两个键均为空后才发送带代次的回执。主进程只有收到当前代次的有效回执才设置 `cleanupVerifiedAt`，失败或超时后重试。

## 时间规则

- 固定使用 `Asia/Shanghai`，时间格式为 `HH:mm`，日期格式为 `YYYY-MM-DD`。
- 时间段为左闭右开：到达 `end` 的那一刻立即进入上课。
- `end` 早于 `start` 表示跨午夜；起止相同会被拒绝。
- 每周时间段按星期重复，特殊日期替代当日每周表，停用日期当日无课间。
- 每周和特殊日期均检查同日及跨午夜重叠。
- 配置保存在主进程 `campus-config.json`，通过临时文件和重命名原子替换。

## 恢复与跳变

调度器使用绝对时间计算状态，以边界定时器和一秒校验共同触发。系统恢复、解锁和配置变化都会立即重算。应用启动时先初始化为 `TRANSITIONING`，调度服务就绪前不允许播放；渲染层在历史队列和历史歌曲恢复之前向主进程报到。

“结束当前课间”只在当前课间原定结束时间前强制保持 `CLASS`，不会改写永久时间表。
