# 课间调度与硬截止

首次安装没有预设学校作息。在设置 → 校园点歌配置实际课间，保存并立即应用。周一到周日独立编辑，可复制、启停、删除、排序；特殊日期替换当日每周表，临时停用日期优先。跨午夜课间归开始日期，起点包含、终点排除；检测每周跨日和特殊日期覆盖后的重叠。

## 硬截止顺序

1. 主进程同步进入 CLASS，递增 generation，立即原子持久化 pendingClear 标记
2. 执行完整停止，作废 loadSeq、预载、交接、设备恢复和播放会话
3. 向前端广播快照；渲染端立即使 loadToken / trackToken 失效，停止原生引擎（空队列也执行），重置索引、当前曲目信息、封面和播放进度
4. 串行写入空 playList 与 null originalPlayList，等待完成并回读验证
5. 前端按唯一 eventId 确认；主进程只接受当前 pendingClear ID，旧确认不能解除新锁定
6. 保持 CLASS 至下一次课间；若清理未确认，下一课间仍拒绝播放

主进程不等待 UI 完成才停止音频。前端尚未加载、隐藏、重载或清理失败均不会解除主闸门。故障恢复后可重新获取快照并重试；日志记录停止原因和唯一事件。

## 启动与恢复

每次启用校园模式启动均清空历史会话，即使此时已经在课间，也不恢复上一课间任务。主进程调度先于窗口创建；渲染端桥接先于队列恢复，校园模式跳过原历史恢复流程。

定时器按下一绝对边界 setTimeout，15 秒补偿校验；resume、unlock-screen、窗口聚焦和配置修改立即重算。原生播放闸门每次实际调用也重算时间，防止定时器延后或时钟前跳时放行。系统休眠错过一个或多个课间时，当前 activeId 的变化先产生清理，之后才可进入新课间。

手动「立即结束」记住当前课间 ID，同次课间不重新开放。关闭调度后恢复普通播放权限；尚未完成的清理需要先完成确认。永久歌单、下载、历史、音乐文件和 B 站 Cookie 不属于定时清理范围。

## 测试

`schoolScheduler.spec.ts` 使用假时钟验证启动、边界、休眠跨课间、时间跳变、关闭、手动结束、配置变更、重复确认、跨午夜、特殊日期和重叠。`schoolPlaybackGate.spec.ts` 验证实际原生调用被阻止；`queuePersistence.spec.ts` 验证迟到旧写入和恢复竞态。Windows 的真实扬声器输出、睡眠/唤醒、托盘和媒体键需要实体机器完成最终声学验收。

## 迟到事件与失败重投

清空期间拒绝前端旧 status、position、ended 和过渡事件，防止界面回到 playing 或再次切歌。历史恢复、标签写入后的恢复和热重载均验证播放操作代次；同一结束事件已确认后，重复快照不会误清下一课间的新队列。

清理未获确认时，15 秒补偿检查会重投同一 pendingClear 事件，不生成新的停止事件。磁盘操作或播放器暂未就绪导致的清理失败保持锁定，恢复后可重试并确认。
