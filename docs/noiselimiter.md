# NoiseLimiter

默认开启「动态限制」，强度 50，输出上限 −12 dBFS。动态与基础模式各自保存 0–100 的强度，上限范围 −30 至 −3 dBFS。界面只显示控件、数值、状态和错误，不放说明段落。

## 处理路径

原生音乐在交叉混音、均衡、归一化与最终音量之后，进入按完整音频帧处理的 Rust DSP；CPAL 与 Windows WASAPI 共用该出口。参数使用单个原子快照，实时回调不分配内存、获取锁或调用脚本。预分配 5 ms 延迟，所有声道联动，最终限制输出峰值。

B 站普通浏览和哔哩Song 使用同一份 Rust 算法编译出的本地 WASM，经 AudioWorklet 处理。主世界在站点首次脚本前拦截媒体播放；初始化期间先连接保守限幅图，随后切换 WASM。网页不能通过诊断回报修改应用参数。参数修改不重载网页，也不主动恢复暂停的视频。受跨域限制而无法安全接入音频图的媒体暂停并显示错误。

「基础限制」采用全频带包络压缩和最终限幅。「动态限制」将信号分为低、中、高频检测与残差重组，对过强低频鼓点、高频尖叫施加更有针对性的动态衰减。两者都没有自动补偿增益。动态处理改变的是音频幅度与频段能量，不能识别并完整分离人声、尖叫和乐器，也不能根据 dBFS 保证扬声器的实际声压；现场仍需设置系统音量。

插件异常时保留最后有效上限并退到基础保护，非法配置不覆盖现有参数。浏览器处理器故障退到保守限幅；本地资源校验失败或原生保护不可用则阻止播放。用户明确禁用、撤销 DSP 权限或卸载时才移除该插件贡献。多个插件组合时上限取最严格值，不允许一个插件抬高另一个插件的上限。上课清理仍释放原生音频并作废网页和恢复任务。

## 固定来源与许可

包络、软拐点增益与限制算法参考并改写自 CamillaDSP，固定提交 `05e9cfcdf43c0dfe078ed3feb8af4c8bd701fd74`。上游提供 GPL-3.0 / MPL-2.0 双重许可，此处改写文件选用 MPL-2.0；上游原文件和两份许可证保留在 `vendor/noiselimiter/camilladsp`。整体应用继续使用 AGPL-3.0。

`native/noise-dsp` 是无第三方依赖的可移植 crate，`pnpm test:dynamics` 测试，`pnpm build:dynamics` 编译 WASM、写入 SHA-256 清单。`pnpm pack:noiselimiter` 生成可导入 ZIP。应用只执行本地固定资源，不在线下载 DSP。

## 验证范围

可控信号测试覆盖静音、NaN/Inf、混合峰值、鼓点/高频突发、强度、模式切换、多采样率与声道、无效配置及旁路。AudioWorklet 测试实际加载 WASM，并故障注入检查限幅后备。真实 Chromium 中 −12 dBFS 峰值约 0.2511886，实时改为 −18 dBFS 后约 0.1258925，页面没有重载。

真实 B 站样本验证输出图连接、音频上下文 running、非零峰值与上限；此结果不代表所有视频或实体扬声器的主观效果均已验收。
